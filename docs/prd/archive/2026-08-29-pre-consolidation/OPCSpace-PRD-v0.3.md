# 1. 产品背景与目标

## 1.1 产品定位

OPCSpace 是面向园区入驻企业和物业运营团队的企业服务平台。入驻企业通过微信小程序查看内容、提交服务信息和查询业务记录；招商、财务、运营、内容和超级管理员在管理端查看并处理对应信息；统一后端负责身份、权限、业务数据和跨端查询。

## 1.2 当前目标

1. 完整识别小程序已有入口和管理端已有信息处理功能。
2. 建立小程序入口、信息对象、管理端处理页面和返回展示之间的稳定关联。
3. 区分原型事实、当前范围、候选设计和正式实现，避免把演示成功态当成真实能力。
4. 为下一阶段逐条业务闭环评审提供唯一功能集合基线。

## 1.3 当前非目标

- 本版不确认每条业务已经形成闭环。
- 本版不冻结 API、数据库表、审批链、SLA、支付渠道和外部厂商协议。
- 本版不建设物业工程设备、巡检、维保和实时监控系统。
- 本版不声明冻结原型已经由正式代码实现。

# 2. 用户角色与场景

## 2.1 小程序角色

| 角色 | 主要场景 |
|---|---|
| 企业成员 | 查看园区信息，提交本人有权限的服务信息，查看本人或获授权的业务记录 |
| 企业管理员 | 查看企业档案，管理成员，代表企业发起或查看获授权业务 |
| 访客 | 使用被签发的访客通行凭证，在授权时间和区域完成核验 |

## 2.2 管理端角色族

| 角色族 | 主要责任 |
|---|---|
| 招商 | 企业、合同、续租、入驻、装修、退租和企业服务协同 |
| 财务 | 账单、收款、对账、充值、发票、押金和企业对账单 |
| 运营 | 报修、投诉、环境服务、空间、停车业务、访客通行和客服协同 |
| 内容 | 公告、Banner、活动、政策/企业服务产品和 AI 服务商品 |
| 超级管理员 | 后台账号、角色权限、消息规则、审计、配置发布、隐私和数据治理 |

五个角色族是权限与责任分类，不限制业务页面数量；统一待办、审批、消息和审计是跨角色共用能力。

# 3. 核心问题与价值

| 当前问题 | 产品价值 |
|---|---|
| 小程序入口和管理端页面分别存在，但信息对象关系不清 | 建立稳定的 `MP-* → FC-* → 管理端页面` 追溯关系 |
| 原型、候选流程和正式实现状态混用 | 明确原型证据、当前范围、候选设计和已实现四种状态 |
| 同一业务分散在多个后台页面 | 用功能联动集合明确哪个页面查看、处理和返回哪些信息 |
| 范围包含不需要的工程设备和巡检能力 | 删除物业工程内管范围，聚焦企业服务和运营协同 |
| 访客硬件容易被与其他硬件一并删除 | 将访客门禁硬件列为明确保留的业务例外 |

# 4. 产品范围

## 4.1 小程序功能范围

当前原型包含首页、服务、AI、我的四个一级入口，14 个“全部服务”入口，以及通知、企业成员、历史记录、客服、反馈和合规信息。完整入口、页面动作和编号以功能联动事实集合为准。

## 4.2 管理端功能范围

当前产品使用以下信息处理域：

| 信息处理域 | 当前范围 |
|---|---|
| 招商 | 企业、合同、续退租、入驻/装修申请信息 |
| 财务 | 账单、收款对账、发票、电费账户与充值、押金、对账单 |
| 运营 | 报修、投诉、环境服务、空间预约、停车业务信息、访客通行 |
| 内容 | 公告、Banner、活动、企业服务产品、AI 服务与订阅、产品反馈 |
| 超级管理员/共用治理 | 用户成员、隐私、审批、客服、AI 运营、自动化、账号、权限、消息、审计、配置和数据质量 |

## 4.3 明确排除

以下原型内容保留在证据清单中，但不进入当前产品需求：

- `ADM-03-01` 设备台账；
- `ADM-03-02` 设备详情和实时参数；
- `ADM-03-03` 巡检计划；
- `ADM-03-04` 维保与设备告警；
- 施工人员台账中的每日物业巡检、设备整改巡检；
- BA、传感器、设备实时监控、设备告警自动转单；
- 停车硬件控制和电表设备管理。

## 4.4 明确保留的硬件例外

访客预约与通行保留完整硬件信息联动：访客邀请、审批、二维码/通行码、门禁授权、闸机事件、核销、撤销失效、设备离线和人工放行。

普通报修继续保留，但处理主体统一称为运营服务人员，不连接设备台账、巡检或维保告警。

# 5. 信息架构与功能联动

## 5.1 统一追溯关系

```text
小程序入口 MP-*
  → 功能联动集合 FC-*
  → 管理端信息处理页面
  → 小程序可见信息或业务记录
```

当前共 22 个 `FC-*` 功能集合，覆盖 52 个小程序稳定编号和 38 个原型页面标识。功能集合只陈列信息来源、处理位置和返回展示，不判断审批、执行、通知和异常是否已经闭合。

## 5.2 跨业务共用能力

| 共用能力 | 作用 |
|---|---|
| 统一待办 | 汇总不同业务等待管理人员处理的信息 |
| 统一审批 | 展示不同业务产生的审批任务和处理记录 |
| 消息规则 | 将业务信息变化映射为小程序通知类别和发送通道 |
| 权限 | 按角色族、项目、企业和业务对象控制数据范围和操作 |
| 审计 | 记录管理端关键操作人、对象、时间和结果 |
| 配置发布 | 管理小程序入口、开关和版本 |

当前禁止把 D1—D4 的候选内容描述为已确认或已实现。

# 附录 A：文档状态词

| 状态词 | 定义 |
|---|---|
| 原型证据 | 冻结原型存在页面、字段或交互 |
