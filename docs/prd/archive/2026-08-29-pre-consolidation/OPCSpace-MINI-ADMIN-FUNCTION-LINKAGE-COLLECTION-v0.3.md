## 1. 本轮目标和边界

本文只回答三个问题：

1. 小程序原型现在有哪些用户可见功能入口；
2. 管理端原型有哪些页面可以接收、查看或处理这些入口产生的信息；
3. 从现有原型能够确认的功能联动路径是什么。

本文不评价流程是否闭环，不补造业务规则，不把原型按钮解释成正式能力。

管理端“招商、财务、运营、内容、超级管理员”是角色责任族，不是只保留五个功能；统一待办、审批、客服、消息、审计和配置属于跨角色共用处理能力。

### 1.1 当前代码事实

| 代码区域 | 当前事实 | 本文使用方式 |
|---|---|---|
| `apps/admin-web/` | 只有正式工程边界 README，没有管理端业务源码 | 不作为功能已实现证据 |
| `apps/mini-app/` | 若依 App 基座快照，尚未实现 OPCSpace 身份、工单和业务页面 | 不作为 OPCSpace 功能已实现证据 |
| `services/backend/` | 若依后端基座，`opc-*` 业务模块尚未建立 | 不推断真实接口、数据库或状态流转 |
| `prototypes/mini/` | 可运行的小程序浏览器交互原型 | 小程序入口和页面动作事实来源 |
| `prototypes/admin/` | 可运行的管理端交互原型 | 管理端页面和信息处理动作事实来源 |

因此，本文所有“已有功能”均指冻结原型已有，不代表正式代码已经交付。

### 1.2 本轮范围规则

| 范围 | 处理方式 |
|---|---|
| 设备台账、设备详情、巡检计划、维保与设备告警 | 不进入本次联动集合 |
| 施工人员台账中的每日巡检、整改巡检 | 不进入本次联动集合 |
| 普通报修 | 保留，作为运营服务信息处理，不关联设备台账和巡检 |
| 访客预约与通行硬件 | 明确保留，包括二维码、门禁授权、闸机事件、核销、设备离线和人工放行 |
| 停车 | 保留车辆、月租、优惠、账单、缴费和记录等业务信息；本轮不延伸设备控制 |
| 电费 | 保留账户、账单、充值、回单和入账信息；本轮不延伸设备台账或巡检 |

## 4. 小程序—管理端功能联动流程集合

以下“联动”表示两个原型中存在相应信息展示或处理页面，不表示真实接口已经建立。

### FC-00 客户端导航与服务入口

| 项目 | 内容 |
|---|---|
| 小程序入口 | 返回、关闭、底部首页/服务/AI/我的、全部服务 |
| 小程序动作 | 页面导航、服务目录选择、功能入口跳转 |
| 管理端关联 | `system-config-publish` |
| 管理信息处理 | 查看和发布小程序配置项、入口开关、版本和白名单 |
| 联动路径 | 管理端配置发布信息 → 小程序入口展示与跳转 |

## 5. 共用管理处理链

## 7. 下一阶段讨论边界

本文件冻结后，下一阶段再针对每个 `FC-*` 讨论：小程序提交的信息是否完整、管理端是否有明确责任人和处理动作、处理结果是否回到小程序、异常如何反馈，以及流程能否称为闭环。本文件本身不预设这些结论。
