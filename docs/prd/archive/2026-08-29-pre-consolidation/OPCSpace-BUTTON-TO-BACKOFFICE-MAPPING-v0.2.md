# OPCSpace 小程序—管理端候选承接评估 v0.2

> 文档状态：历史候选承接与缺口分析；当前阶段不据此认定业务闭环。
> 当前产品基线：[PRD v0.3](./OPCSpace-PRD-v0.3.md)；当前功能事实：[功能联动集合 v0.3](./OPCSpace-MINI-ADMIN-FUNCTION-LINKAGE-COLLECTION-v0.3.md)。
> 小程序基线：`OPCSpace-MINI-PROTOTYPE-FUNCTION-INVENTORY-v0.2.md`
> 管理端基线：`OPCSpace-ADMIN-PROTOTYPE-FUNCTION-INVENTORY-v0.2.md`
> 重要边界：本文件判断的是“原型设计上是否存在合理承接点”，不是“系统已经实现”。当前正式工程仍没有 OPCSpace 业务 API、数据库迁移和真实跨端状态闭环。
> 范围约束：工程设备、物业巡检、维保告警相关结论已废弃；访客通行硬件保留。

## 1. 映射方法

本次映射严格以小程序 `MP-*` 为主索引，按下列顺序逐项判断：

1. 用户在小程序看到了什么、点击了什么；
2. 是否产生业务记录、审批、执行任务、配置或仅是本地交互；
3. 管理端哪个 `ADM-*` 页面承接同一个业务对象；
4. 管理员处理后，小程序是否有状态、通知和最终结果可回看；
5. 失败、撤回、并发、越权和人工补偿是否有位置处理。

### 1.1 承接等级

| 等级 | 含义 |
|---|---|
| A 明确承接 | 管理端已有同一业务对象的列表、详情和关键处理动作，仍需补接口与规则实现 |
| B 部分承接 | 有相近页面，但缺状态、字段、用户回看、异常处理或跨页协作 |
| C 无合理承接 | 没有专用页面/动作，不能靠同名或通用页面代替 |
| D 无需管理端 | 返回、Tab 切换、本地筛选等纯客户端动作；仍可能需要配置或埋点 |

所有 A/B/C 项的实现状态均为“未实现”；A 只表示原型信息架构较完整。

## 14. 管理端有页面但不是小程序申请承接的能力

这些页面有独立运营价值，但不能被误认成某个前台按钮的直接后端：

| 管理端范围 | 性质 | 说明 |
|---|---|---|
| ADM-01-01 至 ADM-01-05 | 运营观察与调度 | 汇总看板、待办、分析、预警、值班，不持有领域主状态 |
| ADM-03-01 至 ADM-03-04 | 原型证据，当前排除 | 设备台账、巡检、维保和告警不进入当前产品，也不与小程序报修联动 |
| ADM-05-05 | 施工人员治理 | 服务装修入驻流程，但不等于企业的装修申请主单 |
| ADM-09-01 | 统一审批 | 承载审批任务，不替代领域申请单和状态机 |
| ADM-09-04 | 事件自动化 | 消费领域事件，不应直接修改无审计的业务状态 |
| ADM-10-01 至 ADM-10-07 | 系统治理 | 提供账号、权限、消息、审计、数据质量、配置发布和状态投影底座 |

## 15. 缺口汇总

### 15.1 必须新增或拆分的前台设计

1. 个人资料详情/变更；支付收银台和支付中/失败；活动详情与报名表单。
2. `09` 工单列表/详情、`23` 我的预约/预约凭证拆分稳定路由；两个 `15` 页面改为不同编号。
3. 缴费记录设置正式入口；AI 普通会话历史与敏感动作草稿历史分层。
4. 装修、入驻、退租拆为三套可提交、可补件、可撤回、可验收的流程。
5. 停车聚合页下补车辆、月租、临停订单、优惠券和账务异常详情，不包含停车硬件控制。
6. 所有写动作补提交中、成功、失败、重复提交、无权限和状态冲突反馈。

### 15.2 必须新增或加强的管理端设计

1. 服务目录/小程序入口编排主数据，不只做配置发布记录。
2. 评价与回访工作台；协议/隐私文档版本管理；个人/企业资料变更审核。
3. 活动候补递补、空间库存锁、访客黑名单/实名、停车业务账务异常处置。
4. 支付订单、退款、发票红冲、账单异议、差异入账和失败补偿台。
5. 入驻/装修/退租各自的领域主单、材料、整改、验收、交割与押金链路。
6. AI 动作草稿的业务校验、权限快照、审批路由、人工接管和结果回写。

## 16. 总结

从页面信息架构看，报修、访客、对公充值等已经有相对明确的前后台承接骨架；但没有任何业务仅凭当前冻结原型就可以判定为完整闭环。主要原因不是“后台页面数量少”，而是申请对象、领域状态、用户回看、通知、异常与补偿尚未被统一定义。下一份详细设计应直接引用本表的 `MP-* → ADM-*` 关系，为每条业务线补齐对象、状态、角色、页面、API、事件和验收用例。
