# OPCSpace 管理端原型功能全量清单 v0.2

> 文档状态：原型事实盘点基线
> 盘点对象：`prototypes/admin/` 冻结原型
> 盘点方法：逐个展开一级菜单并访问每个二级路由，记录页面标题、嵌入区块、按钮动作和主要数据对象；本文件只陈述管理端原型事实，不提前映射小程序。
> 产品范围以 [PRD v0.3](./OPCSpace-PRD-v0.3.md) 为准：本清单完整保留原型证据，但 `ADM-03-01` 至 `ADM-03-04` 及施工每日巡检不进入当前产品；访客门禁硬件保留。

## 1. 盘点口径与总览

| 项目 | 口径 |
|---|---|
| `ADM-xx` | 管理端一级功能组稳定编号 |
| `ADM-xx-xx` | 该一级组下的二级页面稳定编号 |
| 页面嵌入功能 | 页面内的卡片、Tab、图表、明细区、规则区、时间线、抽屉或弹层 |
| 页面动作 | 新建、编辑、审核、派单、导出、筛选、启停、发布、回滚等原型控件 |
| 数据对象 | 页面表格/列表/详情实际围绕的业务记录 |
| 事实边界 | 有页面或按钮只证明原型表达，不证明 API、权限、状态机或真实数据已实现 |

### 13.2 不能由管理端原型单独证明的事项

1. 菜单相似不代表能接住小程序提交；必须核对同一业务对象、企业边界、状态与数据字段。
2. 有“审核”“通过”“派单”按钮不代表审批规则、权限、幂等和审计已经实现。
3. 有趋势图和列表不代表存在真实统计口径、数据库表或接口。
4. `统一待办`、`统一审批`、`事件自动化` 是跨业务治理入口，不能替代报修、账单、预约等领域自身的状态机。
5. `小程序配置发布` 只能管理入口/配置版本，不能替代具体业务模块。
6. 原型里部分详情、弹层和按钮可能用静态数据演示，正式设计必须补全空态、错误态、无权限态、并发冲突和补偿操作。

## 14. 后续使用规则

本清单冻结后，以 `ADM-xx-xx` 为唯一管理端页面引用编号。下一阶段以小程序清单中的每一个 `MP-*` 功能为主索引，逐项判断：

1. 是否存在一个或多个明确的管理端承接页面；
2. 承接的是申请受理、审批、执行、配置、运营观察还是系统治理；
3. 是否存在用户可回看的状态、通知和最终结果；
4. 是否缺少管理端页面、页内动作、业务规则、数据字段或异常处理；
5. 是否只是“菜单名称相似”，实际上没有形成同一业务对象的闭环。

在完成上述逐项核对前，不应使用“管理端已经有这个菜单”作为闭环成立的判断依据。
