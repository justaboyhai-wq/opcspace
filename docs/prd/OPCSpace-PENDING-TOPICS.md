# OPCSpace PRD 待确认事项

> 本清单只记录会影响产品规则、范围或验收的未决问题。未确认前不得由研发自行假设为正式制度。

## P0：进入 Alpha 详细设计前必须确认

| ID | 主题 | 需要确认的结论 | 建议责任人 | 未确认时默认处理 |
|---|---|---|---|---|
| P0-01 | 物业组织与角色 | 客服、工程、值班、主管的真实部门、岗位、派单/转派/关闭权限 | 物业负责人 | 仅启用最小客服与工程角色，不做自动分派 |
| P0-02 | 项目与空间数据 | 和盛大厦楼宇/楼层/空间编码、企业占用关系、数据责任人 | 物业+招商 | 使用脱敏开发种子，不作为验收数据 |
| P0-03 | 报修分类与 SLA | 分类、优先级、服务时间、首次响应/到场/完工时限、升级人 | 客服+工程主管 | 只记录时间，不据此自动处罚或承诺 |
| P0-04 | 工单撤回/挂起/重开 | 可操作窗口、理由、SLA 是否停表、用户重开期限 | 客服+工程主管 | 高风险分支人工处理并完整留痕 |
| P0-05 | 验收与自动关闭 | 谁可代验收、几次提醒、多久自动关闭、低分如何回访 | 物业负责人 | 不自动关闭，由客服人工确认 |
| P0-06 | 成员唯一性 | 同一手机号能否加入多个企业、企业切换、离职后历史可见性 | 物业+法务/隐私 | 允许多关系但每次选择当前企业；历史最小可见 |
| P0-07 | 激活与换绑 | 激活信息发送渠道、手机号验证、微信换绑/解绑和遗失处置 | 产品+安全 | 只允许管理员重发；换绑必须人工核验 |
| P0-08 | 附件规则 | 图片/视频类型、数量、大小、保留期、敏感内容和病毒扫描 | 产品+安全+运维 | 仅图片、小数量、私有桶、扫描通过后绑定 |
| P0-09 | 个人信息 | 手机号/姓名/微信身份的收集告知、用途、留存、导出和删除流程 | 法务/隐私负责人 | 最小收集、默认脱敏、禁止批量导出 |
| P0-10 | Alpha 验收主体 | 试点企业、真实验收人、试运行周期和签字标准 | 项目负责人 | 不进入生产，只完成 staging 验证 |

## P1：进入 MVP 开发前确认

| ID | 主题 | 需要确认的结论 | 建议责任人 |
|---|---|---|---|
| P1-01 | 投诉匿名 | 是否允许匿名、哪些角色可解密、法定留存和升级规则 | 物业+法务 |
| P1-02 | 空间预约 | 资源目录、开放时段、审批人、取消/爽约、收费与凭证规则 | 运营负责人 |
| P1-03 | 访客 | 最小必要信息、审批条件、访问区域、二维码机制、人工放行 | 安保+法务 |
| P1-04 | 内容发布 | 公告/活动受众、复核、紧急发布、撤回、评论与报名规则 | 内容运营 |
| P1-05 | 消息渠道 | 站内信、微信订阅消息、短信的使用场景、模板与用户同意 | 运营+法务 |
| P1-06 | 客服与投诉关联 | 会话转工单、投诉转工单、重复问题合并和责任归属 | 客服主管 |
| P1-07 | 数据指标 | 服务量、SLA、满意度、一次解决率的口径和业务基线 | 运营+数据 |
| P1-08 | 运行指标 | 并发、P95、可用性、RPO/RTO、值班和告警门槛 | 技术+运维 |

## P2：进入 V1/V1.5 前确认

| ID | 主题 | 需要确认的结论 | 建议责任人 |
|---|---|---|---|
| P2-01 | 资产与巡检 | 现有资产台账来源、编码、维保商、巡检规则与告警来源 | 工程负责人 |
| P2-02 | 租赁权威系统 | OPCSpace 是合同权威源还是既有系统的业务前台 | 招商+财务 |
| P2-03 | 财务权威系统 | 费项、账单、会计日期、减免、对账和关账由谁负责 | 财务负责人 |
| P2-04 | 支付与发票 | 渠道/服务商、商户号、退款、电子发票和沙箱协议 | 财务+法务+技术 |
| P2-05 | 门禁与停车 | 厂商、设备协议、回调、离线策略、人工补偿和 SLA | 安保+技术 |
| P2-06 | AI 范围 | 仅问答或允许动作草稿、知识源、引用、成本和风控负责人 | 产品+安全+业务 |
| P2-07 | 多项目扩展 | 同一物业多项目的组织、数据权限、品牌和配置继承方式 | 管理层+产品 |

```text
决策 ID：
结论：
适用版本：
业务负责人：
技术/合规复核人：
生效日期：
关联 PRD/流程/原型：
被替代的旧规则：
```

P0 全部关闭后生成 PRD v0.3；P1/P2 可以不阻塞 Alpha，但不得在页面文案或排期中暗示已经确定。
