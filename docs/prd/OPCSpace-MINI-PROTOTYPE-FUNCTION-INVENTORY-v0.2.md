# OPCSpace 小程序原型功能全量清单 v0.2

> 文档状态：原型事实盘点基线
> 盘点对象：`prototypes/mini/` 冻结原型
> 盘点方法：逐页打开编号页、未编号页、变体页和弹层，记录可见入口、按钮、表单动作及观测结果；本文件只陈述小程序原型事实，不提前映射管理端。

## 1. 盘点口径

| 项目 | 口径 |
|---|---|
| `MP-Gxx` | 跨页面共享的全局壳层或入口 |
| `MP-xx` | 原型中的编号页面；编号是本次稳定编号，不等同于原型原始序号 |
| `MP-Uxx` | 未编号页面、变体或弹层 |
| 入口 | 从首页、服务、我的、列表、详情、消息或 AI 能实际触达的控件 |
| 页内动作 | 表单提交、筛选、切换、确认、取消、上传、联系、下载/查看等动作 |
| 观测结果 | 仅记录原型发生的跳转、弹层或本地成功态，不推断真实后端能力 |
| 待确认 | 原型没有给出规则、结果或稳定路径，不能凭页面文案补造 |

本次识别出 38 个原型编号段中的页面定义，但原始编号存在缺号和复用：没有 `06`；`15` 被两个不同页面复用；`09`、`23` 各包含两个语义不同的页面变体。另识别到 AI 草稿历史及敏感动作草稿详情等未编号能力。

## 15. 覆盖核验与原型问题

### 15.1 页面覆盖

| 核验项 | 结果 |
|---|---|
| 原始编号页 | 已遍历 `01—05、07—38` |
| 缺号 | 原型无 `06` |
| 重号 | 原型 `15` 同时用于“缴费成功/开票引导”和“发票申请” |
| 同 ID 多语义变体 | `09-repair-progress` 同时承载列表/详情；`23-space-booking-pass` 同时承载预约凭证/我的预约列表 |
| 未编号能力 | AI 草稿历史、AI 敏感动作草稿详情、AI 意图路由 |
| 疑似孤儿页面 | `33-payment-records` 在主要可见入口中的显式到达路径不稳定 |
| 无落地跳转控件 | “查看个人资料”点击后仍停留 `04-profile` |
| 跳步问题 | 活动卡片直接进入“报名成功”，缺失详情与确认过程 |

### 15.2 本清单冻结前仍需人工复核的点

1. 设计方是否有未交付的 `06` 页面或私有分支。
2. `09`、`15`、`23` 的复用是演示实现问题，还是业务上计划合并路由。
3. `33-payment-records` 的正式入口应放在“账单与发票”、账单中心还是独立记录页。
4. “查看个人资料”预期展示哪些字段、是否允许修改与实名变更。
5. AI 管家普通会话历史是否另有页面，还是与动作草稿历史合并。

## 16. 后续使用规则

在本清单冻结前，不得据此直接宣布任何业务已经闭环。冻结后，以 `MP-Gxx / MP-xx / MP-Uxx` 为唯一小程序侧引用编号，逐项去管理端清单查找承接页面；没有承接点、状态、规则、通知、用户回看或异常处理的项目，必须明确列为缺口，而不是用相近菜单名代替。
